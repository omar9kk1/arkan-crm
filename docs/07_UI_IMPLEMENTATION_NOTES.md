## Evolving Design and Component System

- البروتوتايب مرجع بصري قابل للتطوير، وليس تصميمًا نهائيًا مطلوب نسخه pixel-perfect.
- سنعدل التصميم وسلوك الاستجابة للشاشات أثناء التنفيذ؛ يجب أن تكون هذه التعديلات سهلة ومركزية.
- استخدم مكونات صغيرة قابلة لإعادة الاستخدام، مع فصل مكونات UI العامة وLayout عن مكونات كل feature.
- اجمع القيم المتكررة في design tokens مشتركة: الألوان، المسافات، الخطوط، الأحجام، الزوايا، الظلال، طبقات العرض، والحركة.
- استخدم نهج تنسيق متسق؛ نقطة البداية CSS custom properties للـtokens وCSS Modules لتنسيق المكونات، مع حصر CSS العام في الأساسيات.
- إذا اعتُمد Tailwind لاحقًا، اربط إعداداته بنفس tokens بدل إنشاء مصدر تصميم موازٍ.
- اجعل Cards وButtons وDrawers وModals وMobile Nav مكونات مشتركة ذات variants واضحة، تُضاف عند الحاجة.
- لا تكرر قيم التصميم أو أنماط inline الثابتة داخل كل مكون؛ التعديل على النمط المشترك يجب أن ينعكس على جميع استخداماته.
- حافظ على RTL وbreakpoints متسقة، واجمع السلوك المتكرر للاستجابة داخل المكونات المشتركة.
- هذه قواعد للتنفيذ القادم؛ لا تعني البدء في بناء جميع الواجهات أو المكونات الآن.

## Important UI Decisions

- النظام عربي RTL.
- تصميم هادي بألوان بيج/ذهبي فاتح.
- تجنب البني الغامق قدر الإمكان.
- البار السفلي في الموبايل لا يزيد عن 5 أزرار.
- زر More يحتوي الصفحات الإضافية.
- في صفحات المدير:
  - Search bar في نفس المكان في كل صفحة تحتاج بحث.
  - Side drawer للتفاصيل.
  - Forms لازم تكون responsive.
- صفحة العقارات:
  - كروت منظمة حسب المنطقة.
  - الضغط على كرت العقار يفتح Drawer.
  - Drawer يعرض:
    - تفاصيل العقار.
    - المالك.
    - الموظفين المتابعين مع المالك.
    - تبويب لكل موظف يعرض سجل متابعته مع المالك.
- صفحة المالية:
  - كل حركة مالية قابلة للضغط.
  - التفاصيل توضح مصدر الحركة والتاريخ والطرف والصفقة والعقار والعمولة.

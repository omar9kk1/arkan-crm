# درج تفاصيل العقار: زر الحذف وربط العقار المباع بصفقته

**التاريخ:** 2026-11-12
**النطاق:** درج تفاصيل العقار (Manager Properties) فقط — واجهة أمامية.
**الحالة:** مكتمل، بدون تغيير خادم أو قاعدة بيانات أو منطق حذف/بيع/عمولات.

---

## 2. زر الحذف

- النص المرئي أصبح: **«حذف»** بدل «حذف إلى سلة المحذوفات».
- أُضيفت أيقونة `trash` الموجودة في `components/ui/icon.tsx` بجانب النص، بلون `--danger` الأحمر.
- الزر بقي `variant="ghost"` في مكانه، ومنطق الحذف نفسه (`onAction('حذف')` → حوار `TrashDeleteDialog` → `trashProperty`) لم يتغير إطلاقاً.
- `aria-label` بقي وصفياً (`حذف <code> إلى سلة المحذوفات`) دون تغيير السلوك.

---

## 3. ربط العقار المباع بالصفقة

- العرض مشروط بثلاثة شروط معاً:
  1. `property.apiStatus === 'SOLD'`.
  2. المستخدم `OWNER` (يُمرَّر عبر `canOpenDeal={canDelete}` حيث `canDelete` للمالك فقط).
  3. وجود معالج فتح صفقة.
- عند فتح درج عقار مباع كمالك، يبحث الدرج في **نقطة الصفقات الموجودة** `GET /deals` (مرتبة `closedAt` تنازلياً) عن أول صفقة تحمل نفس `property.id`، مع متابعة `cursor` حتى نهاية الصفحات إن لزم. أول تطابق هو أحدث/نهائية صفقة للعقار.
- تُحوَّل الصفقة عبر `mapDeal` الموجود وتُسلَّم إلى `DealDetailsDrawer` **الموجود أصلاً** في `manager-deals`؛ لا يوجد تصميم أو درج جديد.
- عند الضغط: يُغلق درج العقار ويُفتح درج تفاصيل الصفقة، ويعرض العميل/المشتري، الموظف المسؤول، العمولات، السعر وتاريخ الإغلاق كما في صفحة الصفقات.
- إن لم توجد صفقة مرتبطة رغم حالة `SOLD`، يبقى الزر مخفياً بعد انتهاء البحث، دون أي خطأ في الواجهة.
- أثناء البحث يظهر الزر معطّلاً، ثم يُفعّل عند العثور على الصفقة.

---

## 4. التحقق

| الحالة | النتيجة |
|---|---|
| عقار غير `SOLD` | لا يظهر زر «تفاصيل الصفقة» |
| `SOLD` + OWNER | يظهر الزر بعد العثور على الصفقة، وينفتح الدرج الصحيح |
| `SOLD` + MANAGER / EMPLOYEE | لا يظهر الزر (الصلاحية تمرَّر للمالك فقط) |
| زر الحذف | النص «حذف» + أيقونة سلة حمراء |
| تخطيط RTL/Responsive | زر الحذف في مكانه، وزر الصفقة في الطرف المقابل عبر `margin-inline-start:auto` مع `flex-wrap` |

| الفحص | النتيجة |

| `npm run typecheck -w @arkan/frontend` | 0 |
| `npx eslint apps/frontend/features/manager-properties apps/frontend/features/manager-deals` | 0 |

لا توجد اختبارات UI آلية في المستودع؛ التحقق من الشروط تم بفحص الشيفرة والصلاحيات الممرَّرة وtypecheck/lint.

## 5. قيود وملاحظات

- البحث يستخدم قائمة الصفقات الموجودة ويجلب الصفحات حتى يجد العقار؛ لدى مالك لديه عدد كبير جداً من الصفقات قد يلزم أكثر من طلب واحد، ويتوقف فور العثور على أحدث صفقة.
- لا يوجد endpoint مخصص `GET /deals?propertyId=...`؛ لم تتم إضافته حفاظاً على نطاق المهمة (بدون تغيير خادم).
- إذا وُجدت صفقات تاريخية متعددة لنفس العقار فالمعروض هو الأحدث حسب `closedAt` (الصفقة النهائية).
- لم يُجرَ نقر يدوي في المتصفح؛ لا تغيير على منطق الحذف أو البيع أو العمولات أو الصلاحيات، ولا `.env` أو ترحيلات أو commit/push.

## 2. سير العمل الدقيق ثلاثي الخطوات

### الخطوة 1: العملية وطريقة الإدخال
- **نوع العملية:** ثلاثة أزرار كبيرة — **بيع** / **إيجار** / **بدل**
- **طريقة الإدخال:** خياران — **إدخال يدوي** / **لصق ذكي من واتساب**
- عند اختيار "لصق ذكي": منطقة نص للصق الإعلان، زر "تحليل النص وتعبئة الحقول"، يعرض ملخص الحقول المستخرجة للمراجعة

### الخطوة 2: بيانات العقار
**لـ بيع/إيجار:** قسم واحد "العقار المعروض"
**لـ بدل:** قسمان في نفس الخطوة:
- أ. **العقار المعروض للبدل**
- ب. **العقار المطلوب في البدل** (جميع الحقول اختيارية)

**الحقول المشتركة للعقار المعروض:**
- المحافظة (مشتق تلقائيًا من المنطقة)
- المنطقة (اختيار من قائمة الكويت)
- القطعة (اختياري، قائمة ديناميكية حسب المنطقة)
- رقم القسيمة/الحوض (اختياري)
- مساحة الأرض / مساحة الوحدة (م²) — أحدها مطلوب
- **الأدوار الديناميكية:** إضافة/حذف أدوار، كل دور له:
  - تسمية (الأرضي، الأول، الثاني، ... أخرى + اسم مخصص)
  - حقل نصي حر واحد **لجميع التفاصيل والملاحظات** (بدلاً من عدادات الغرف المنفصلة)
- **إضافات اختيارية مستقلة:** سرداب، نصف دور، ربع دور — لكل منها حقل نصي حر خاص
- السعر (د.ك) + قابل للتفاوض؟ (نعم/لا/غير محدد)
- **صورة رئيسية واحدة مطلوبة** — رفع من الجهاز، معاينة، استبدال

**العقار المطلوب (بدل فقط):**
- نفس حقول الموقع (اختيارية)
- متطلبات الأدوار (نص حر)
- ملاحظات (نص حر)
- **ميزانية نطاقية:** السعر من / السعر إلى (كلاهما اختياري، التحقق: الحد الأدنى ≤ الحد الأعلى)

### الخطوة 3: المالك أو الوسيط والحفظ
- اختيار نوع جهة التواصل: **مالك** أو **وسيط**
- لكل نوع: **اختيار مسجل** (من السجل المرئي للمستخدم) أو **إضافة جديد** (اسم + هاتف مطلوبان)
- اقتراح سجل مكرر عند تطابق رقم الهاتف
- ملاحظات المصدر
- **ملخص قراءة فقط** صغير قبل زر الحفظ (ليس خطوة رابعة)

## 4. هيكل بيانات العقار المعروض مقابل المطلوب

**نموذج `NewPropertyFormV2`** (`new-property-model-v2.ts`):

```typescript
interface NewPropertyFormV2 {
  // خطوة 1
  entryMethod: 'SMART_PASTE' | 'MANUAL';
  pastedText: string;
  operation: 'بيع' | 'إيجار' | 'بدل';

  // العقار المعروض
  governorate: string;
  district: string;
  block: string;
  plotNumber: string;
  landArea: string;
  unitArea: string;
  floorCount: number;
  floors: FloorEntry[];        // كل دور: id, label, customLabel, details
  hasBasement: boolean;
  basementDetails: string;
  hasHalfFloor: boolean;
  halfFloorDetails: string;
  hasQuarterFloor: boolean;
  quarterFloorDetails: string;
  price: string;
  negotiable: 'قابل للتفاوض' | 'غير قابل للتفاوض' | 'غير محدد';

  // العقار المطلوب (بدل فقط)
  requestedProperty: {
    governorate: string;
    district: string;
    block: string;
    plotNumber: string;
    area: string;
    floorRequirements: string;
    notes: string;
    budget: { min: string; max: string };
  };

  // صورة
  image: PropertyImage | null;

  // خطوة 3: جهة التواصل
  contactType: 'OWNER' | 'BROKER';
  ownerMode/brokerMode: 'EXISTING' | 'NEW';
  ownerId/brokerId, ownerName/brokerName, contactPhone/brokerPhone: string;
  sourceNotes: string;

```

**التحويل إلى `Property`** (`toPropertyFromNewV2`):
- يخزن النموذج الكامل كـ JSON في `description` + قسم نصي للعقار المطلوب (عند البدل)
- يحافظ على `ownerUserId`، `responsibleName`، `contactType`، `imageUrl` للتوافق مع البطاقات والدُرجات
- المدير: `status = 'معتمد'`، الموظف: `status = 'بانتظار الموافقة'`

## 5. الأدوار الديناميكية والإضافات

- **إضافة دور:** زر "إضافة دور" ينشئ دورًا بالتسمية التالية تلقائيًا
- **حذف دور:** زر لكل دور، لا يؤثر على باقي الأدوار
- **تفاصيل الدور:** حقل `textarea` واحد حر لكل دور
- **سرداب / نصف دور / ربع دور:** مربعات اختيار (checkbox) مستقلة، كل منها يظهر `textarea` خاص عند التفعيل
- **صفر أدوار:** مسموح — لا يُفرض عدد أدنى

## 7. سلوك الصورة الرئيسية

- **صورة واحدة فقط** — مطلوبة للعقار المعروض
- رفع من الجهاز فقط (`input[type="file"] accept="image/*"`)
- معاينة فورية (`blob:` URL)
- زر "إزالة الصورة" يبطل `object URL` السابق
- عند الاستبدال: يُبطل الرابط القديم، يُنشأ رابط جديد
- يظهر على كرت العقار، دُرج التفاصيل، ملخص الخطوة 3
- **لا روابط خارجية، لا معرض، لا فيديو**
- `transferred` flag يمنع إلغاء الرابط عند إغلاق النافذة بعد الإرسال الناجح

## 8. تكامل سجل الملاك/الوسطاء

- يستخدم `useVisibleContacts(user, type)` — يرى المدير الكل، الموظف سجلاته فقط
- `contactMode`: `EXISTING` (اختيار من `GlassCombobox`) أو `NEW` (حقول اسم/هاتف)
- `findContactByPhone` يقترح سجلًا موجودًا عند تطابق الهاتف
- `registerPropertyContact` يسجل/يربط الجهة عند الإرسال الناجح
- `ownerUserId` = `AuthUser.id` للموظف، `''` للمدير (سجلات شركة)

## 14. القيود المعروفة

1. **الخصوصية واجهة أمامية فقط** — لا تفويض خلفي، البيانات في الذاكرة/المتصفح
2. **السجل في الذاكرة لكل جلسة تبويب** — يُفقد عند إعادة التحميل، لا يمكن اختبار العزل بين موظفين حقيقيين
3. **الصور `blob:` مؤقتة** — لا تصمد بعد تحديث الصفحة، لا تخزين خلفي
4. **مسودات المعالج القديم** — مفتاح المسودة تغير من `add-property-v2` إلى `add-property-v3`؛ المسودات القديمة لا تُهاجر تلقائيًا (موثق كقيود)
4. **لا توجد اختبارات خلفية** — `apps/backend/test/*.spec.ts` لم تُشغل، لا علاقة لها بتعديلات الواجهة
5. **مسار `companyContactsFor` غير مستخدم** — موجود في `contact-registry.ts`، غير مقيّد، موثق كـ footgun محتمل

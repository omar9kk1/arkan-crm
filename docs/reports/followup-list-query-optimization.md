## 2. التغيير

**الملف:** `apps/backend/src/followups/followups.service.ts`

أُضيف مسار خاص بالقائمة الشخصية فقط، دون المساس بـ`queryPage` المستخدم في supervision:

1. **`queryPersonalPage`**: يُبقي استعلام Prisma للفلاتر والترتيب والـcursor كما هو تمامًا، لكنه يختار **المعرّفات فقط** (`select: { id: true }`، `take: limit + 1`، نفس `cursor/skip/orderBy`).
2. **`subjectCards(ids)`**: استعلام SQL واحد مُعامَل (`Prisma.sql`, `$1::uuid`) يجلب كل حقول البطاقة لتلك المعرّفات:
   - `Property` + `Owner` + `Contact` + `Client`
   - `responsibleUser` أو `responsible.user`
   - آخر `FollowUpEntry` عبر `LATERAL … ORDER BY createdAt DESC, id DESC LIMIT 1`
   - `COUNT(*)` لعدد الإدخالات
   - `ORDER BY array_position(ARRAY[…], s.id)` للحفاظ على ترتيب الصفحة.
3. تُبنى الكائنات بنفس شكل `SubjectRow`، لذلك `toSubjectDto` لم يتغيّر إطلاقًا.

الصلاحيات: استعلام المعرّفات هو نفسه السابق (يحتوي scope المدير/الموظف داخل SQL)، واستعلام البطاقات لا يقرأ إلا معرّفات صادرة من ذلك الاستعلام. لا فلترة بعد الجلب.

**تحديث أداة قديمة:** في `scripts/load-test/verify.cjs` استُبدل الفحص القديم الذي يتوقع `summary` داخل `/follow-ups/manager/overview` بفحص `/follow-ups/manager/summary` (10,556). لم يُغيَّر سلوك التطبيق.

4. **صفحة المتابعات**: أصبحت استعلامين فقط (معرّفات + بطاقات) بدل ~8.
5. **إعادة قياس 100-user** على جهاز هادئ قبل أي حكم على full-mix؛ الأرقام الحالية متأثرة بضغط الجلسة.

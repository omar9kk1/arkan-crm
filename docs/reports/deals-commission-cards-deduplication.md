# تفاصيل الصفقة: إزالة تكرار بطاقات العمولات

**التاريخ:** 2026-11-11
**النطاق:** عرض درج تفاصيل الصفقة فقط (Frontend presentation).
**الحالة:** مكتمل، بدون تغيير في الخادم أو البيانات المالية.

---

## 1. التغييرات الدقيقة

### `apps/frontend/features/manager-deals/components/deal-details-drawer.tsx`

- حُذف القسم المكرر بالكامل: `<h3>تفاصيل العمولات</h3>` وقائمة `<ul>` المتكررة (عمولة الشركة + الموظفين).
- بقيت بطاقات «توزيع العمولات» الأصلية فقط.
- نُقلت عناصر الدفع إلى داخل بطاقتي الموظفين الأصليتين عبر `renderEmployeeAction`:
  - شارة الحالة («بانتظار الدفع» / «تم الدفع · التاريخ» / «ملغاة»).
  - زر «دفع العمولة» للمالك فقط عند `PENDING`.
  - تأكيد مصغّر (اسم الموظف + رمز العقار + المبلغ الدقيق) مع «تأكيد الدفع»/«إلغاء».
  - رسالة الخطأ داخل البطاقة نفسها.
- بطاقة عمولة الشركة بقيت كما هي تماماً بلا أي زر.
- منطق الدفع الحالي لم يتغير: `confirmCommissionPayout` → `POST /finance/commissions/:id/pay`، OWNER-only، تحديث الحالة، وإعادة جلب `GET /deals/:id` مع fallback محلي عند فشل التحديث فقط.

### `apps/frontend/features/manager-deals/components/commission-breakdown.tsx`

- أُضيفت خاصية اختيارية `renderEmployeeAction?: (role) => ReactNode` تُعرض بعد مبلغ كل موظف داخل البطاقة الأصلية.
- بدون الخاصية (مثل خطوة المراجعة في معالج الإنشاء) يبقى المكوّن مطابقاً تماماً لما كان عليه.
- لا تغيير على النصوص أو الترتيب: عمولة الشركة، موظف العقار، موظف العميل.

لا تغيير على CSS أو عرض الدرج أو حقوله الأخرى أو Finance/Notifications UI.

## 2. تأكيد إزالة التكرار

تحقق بالبحث في الشيفرة بعد التعديل:

| العنصر | النتيجة |
|---|---|
| `<h3>توزيع العمولات</h3>` | مرة واحدة فقط في `deal-details-drawer.tsx` |
| «تفاصيل العمولات» | لا توجد أي مطابقة في `apps/frontend` |
| عمولة الشركة | بطاقة واحدة داخل `CommissionBreakdown` |
| عمولة موظف العقار | بطاقة واحدة |
| عمولة موظف العميل | بطاقة واحدة |
| إعادة فتح الدرج/التحديث | الحالة تُقرأ من نفس مصفوفة `commissions` بلا أي تكرار في العرض |

## 3. سلوك الدفع بعد النقل

| الحالة | OWNER | MANAGER |
|---|---|---|
| عمولة `PENDING` | «دفع العمولة» داخل بطاقة الموظف الأصلية | شارة «بانتظار الدفع» فقط |
| تأكيد | بطاقة تأكيد داخل نفس البطاقة | — |
| عمولة `PAID` | «تم الدفع · YYYY-MM-DD» بلا زر | نفس الحالة للقراءة فقط |
| أثناء الطلب | تعطيل الأزرار ومنع التكرار | — |
| فشل الطلب | رسالة داخل البطاقة دون تغيير الحالة | — |

العمولتان مستقلتان، ودفع إحداهما لا يمس الأخرى. لا تتغير مبالغ الصفقة أو التوزيع أو حالة العقار.

## 5. قيود متبقية

- لا توجد اختبارات DOM/UI آلية في المستودع؛ التحقق من عدم التكرار وموضع الأزرار تم بفحص الشيفرة والبحث النصي + typecheck/lint، دون جولة نقر يدوية في المتصفح.

- لا تغيير على الخادم أو قاعدة البيانات أو `.env`، ولا commit/push.
